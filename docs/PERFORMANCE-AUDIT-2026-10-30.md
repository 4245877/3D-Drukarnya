# Аудит производительности анимаций TANMEK — 30 октября 2026

Исходная версия: `efcc822f2191148b2d90a37ce6f292dc9e34e056`. Проверена локальная производственная сборка Astro, а не dev-сервер. Изменения внесены в рабочее дерево; публикация не выполнялась.

## Область аудита

Проверены все общие стили, скрипты и компоненты: главная и фильтры 49 товаров, каталог и категории, товар и галерея, меню, sticky-навигация и панель покупки, контакты, SLA, 404, статьи. Рассмотрены CSS/SVG-анимации, обработчики ввода и прокрутки, чтение геометрии, принудительный layout, наследуемые переменные, циклы вне экрана, создание слоёв, изображения, шрифты и размер клиентского кода.

Сайт уже отдаёт статический HTML без клиентского фреймворка. Фотографии загружаются лениво и декодируются асинхронно; у основных изображений заданы размеры/соотношения сторон. Фон страницы статический, без анимируемого blur или fixed attachment. Эти решения сохранены. Внешние фотографии и Google Fonts остаются отдельными сетевыми зависимостями; их загрузка может влиять на первый показ, но не объясняет постоянную активность CPU после ухода с первого экрана.

## Найденные причины и изменения

1. **Невидимая стойка продолжала работать.** Кольцо и листья уже останавливались через IntersectionObserver, а три LED, импульс кабеля и блик — нет. Все девять циклов главной теперь подчиняются одной `.is-live`. Пауза сохраняет фазу, длительность и исходные задержки. `visibilitychange` приостанавливает анимации скрытой вкладки; `pageshow` синхронизирует состояние после возврата. Переход от reduced motion к обычному режиму тоже обрабатывается.
2. **Движение внутри большого SVG требовало layout и paint.** Статическая стойка, маленькие LED, кабель и блик разделены на слои с исходными координатами. Вращение кольца и движение SLA-платформы перенесены на HTML-обёртки с `transform`; сами SVG-контуры, заливки, тени и порядок перекрытия сохранены. Размер кольца ограничен так же, как у исходного SVG. В результате у главной отсутствует покадровый layout, а у SLA-механизма — и покадровый paint.
3. **Параллакс читал layout для каждого pointermove.** Теперь события собираются до одного requestAnimationFrame. За 240 событий выполняется одно чтение геометрии. Прежние наследуемые `--px`/`--py` на всей сцене заменены непосредственным `transform` её единственного движущегося слоя. Амплитуда, округление координат, направление, 500-мс переход и easing сохранены; одинаковое значение повторно не записывается.
4. **Фильтр принудительно пересчитывал страницу и анимировал весь список.** Удалено чтение `catalogPage.offsetWidth`. Новый планировщик запускает прежнюю волну только для карточек в окне или рядом с ним. Время считается от общего начала фильтрации: отрицательная задержка позволяет карточке при быстрой прокрутке присоединиться к исходной фазе. Сохранены 340 мс, шаг 34 мс, ограничение задержки первыми 12 позициями и прежние keyframes/easing. Через 714 мс наблюдение заканчивается; завершённые классы и задержки удаляются. Быстрые повторные фильтры отменяют предыдущее расписание. Старая reveal-анимация больше не возвращается на уже показанные фильтром карточки.
5. **Лишние записи при прокрутке.** Шапка, активная вкладка товара и панель покупки обновляют DOM только при изменении своего состояния. Для панели покупки сохранены проверки геометрии, необходимые для глубоких якорных переходов и скрытия перед подвалом.

Анимация `stroke-dashoffset` кабеля намеренно сохранена: замена движущимся градиентом изменила бы форму импульса. Она рисует исходную короткую кривую в отдельном маленьком viewport с containment. Единственная новая подсказка `will-change` применяется к этому viewport только у видимой сцены. Containment не добавлен предкам фиксированной панели каталога. Полноэкранные размытия, тени, эффекты hover, моргание, дыхание, уши, листья и переходы между страницами сохранены. Профили качества и скрытие эффектов на слабых устройствах не вводились.

Подход соответствует рекомендациям [web.dev об анимациях и проверке layout/paint](https://web.dev/articles/animations-guide) и [MDN об ограниченном использовании will-change](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/will-change).

## Метод измерений

Windows, Node 22.22.0, установленный Edge 156.0.4314.50 и ранее установленный Playwright. Три профиля: 1440×900 с CPU ×1; 1440×900 с CPU ×6; сенсорный 390×844 с CPU ×6. Исходная сборка сохранена отдельно до изменений. Обе версии обслуживаются одинаковым временным HTTP-сервером; браузер запускается последовательно, чтобы процессы не конкурировали.

На каждом профиле — три повтора видимой главной по 2,2 с с одинаковой начальной фазой циклов (2000 мс). Дополнительно измерены серия pointermove, 2,2 с после ухода с первого экрана, фильтрация, видимый SLA-механизм и портрет 404. Собраны CDP Performance metrics, события Paint/Layout/UpdateLayoutTree и интервалы requestAnimationFrame. `--trace` сохраняет полные трассы при необходимости.

Время `TaskDuration` включает нагрузку измерительного rAF и трассировки. Headless-браузер в этой среде выдаёт интервалы около 5 мс без замедления; это не замер физического экрана телефона. CPU ×6 не эмулирует слабый GPU, память, тепловые ограничения или сетевое соединение. Малые различия времени, в том числе на почти неизменённом портрете 404, считаются шумом окружения, а не доказательством ускорения или замедления. Отчёт не обещает универсальные 60 FPS на любом устройстве.

## Сохранение внешнего вида

Сопоставлены одинаковые кадры при 390 и 1440 px: главная в четырёх фазах (в том числе с активным импульсом), видимый SLA-механизм, SLA-страница и 404 — 14 пар PNG. Геометрия иллюстраций, текст, цвета, композиция и эффекты проверены визуально. При переносе SVG на композитные слои меняется субпиксельное сглаживание; это учитывается в сравнении, а не объявляется попиксельной идентичностью. Проверка ограничивает долю пикселей с отклонением более 16/255 до 0,6% и среднее максимальное отклонение каналов до 0,75/255 на кадр. PNG-разности и точные значения сохраняются в `.performance-qa.tmp/diff/`.

Клиентские зависимости не добавлялись. Для главной суммарный исполняемый JS вырос примерно с 11,1 до 12,6 КБ (gzip 4,6 → 5,2 КБ), CSS — с 69,2 до 71,1 КБ (gzip 16,3 → 16,6 КБ). Небольшая прибавка — планировщик, обработка жизненного цикла и координаты слоёв. Загрузочный бюджет не увеличен тяжёлой библиотекой.

## Повторение

Используется существующий Playwright; сайт не получает новой зависимости. В этой среде:

```powershell
$env:TANMEK_PLAYWRIGHT_MODULE = Join-Path $env:TEMP 'tanmek-contact-qa/node_modules/playwright'
npm run build
npm run check:performance
node scripts/check-performance.mjs --label=baseline --dist=.performance-qa.tmp/before-dist
node scripts/check-performance.mjs --label=baseline-frames --dist=.performance-qa.tmp/before-dist --visual-only
npm run check:performance:frames -- .performance-qa.tmp/baseline-frames .performance-qa.tmp/after
```

На другом компьютере указать путь к своей установленной копии Playwright. `TANMEK_BROWSER_PATH` переопределяет путь Edge/Chrome. Для сравнения будущих изменений сначала сохранить текущий `dist/` отдельно и передать этот каталог через `--dist`. Путь `before-dist` — локальный артефакт этого аудита, в Git он не включён. `--quick` сокращает число повторов, `--profile=desktop-cpu6 --hero-only --no-visual` запускает точечное исследование главной.

Полный регрессионный UI-аудит использует Astro preview, как описано в [FINAL-QA-2026-10-30.md](FINAL-QA-2026-10-30.md).
