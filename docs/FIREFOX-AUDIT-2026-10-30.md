# Firefox / Gecko — аудит совместимости, 30 октября 2026

Проверяется локальная production-сборка Astro с базой `/3D-Drukarnya/`. Исходный commit: `8bc2f4c3895564573c63d7bdb1ea5f20bb76fc23`. Изменения внесены в исходники; публикация не выполнялась. Контент, изображения, цены, маршруты и коммерческая логика сохранены. Клиентские зависимости не добавлялись. Тестовый Firefox хранится в игнорируемом `.firefox-qa.tmp/browsers/`.

## Найдено и исправлено

| Проблема | Исправление |
| --- | --- |
| В Gecko без `animation-timeline` индикатор чтения оставался неподвижной линией. | В `motion.ts` добавлена управляемая прокруткой WAAPI-анимация существующего `::after`. Она использует те же transform/opacity; события объединяются через rAF, диапазон прокрутки обновляется при изменении размеров. CSS-переменные не наследуются всем содержимым шапки на каждом кадре. В Blink остаётся нативный scroll timeline. |
| Firefox понимает `::details-content`, но проверенный Gecko не поддерживает `interpolate-size`; FAQ раскрывался скачком. | `disclosures.ts` измеряет высоты при переключении и воспроизводит исходные 280 мс/easing через WAAPI. Нативные `open`, summary, клавиатура и события сохраняются. Закрываемый контент остаётся видимым до конца перехода. После завершения возвращается естественная высота. Повторное переключение начинает движение с текущего кадра; reduced motion учитывается. В Blink остаётся исходный CSS. |
| Сборщик может нормализовать CSS-время `280ms` в `.28s`. | Fallback переводит обе формы в миллисекунды WAAPI. Промежуточные высоты проверяются в production-сборке. |
| Firefox создаёт клавиатурный click ссылки с `detail=1` и пустым `pointerType`; подсказка Viber не получала фокус. | `contacts.ts` распознаёт оба варианта клавиатурной активации. Нативный URI и модифицированные клики сохраняются. Добавлена регрессионная проверка. |
| Быстрые переключения фотографий оставляли несколько одновременно выполняющихся анимаций opacity. | `ProductGallery.astro` отменяет предыдущий cross-fade перед следующим. Длительность и исходные кадры эффекта сохраняются. |
| Всплывающий `animationend` дочернего элемента мог раньше времени убрать reveal-анимацию родителя. | Очистка в `motion.ts` принимает только собственное завершение `fadeUp`. |
| При активности слоёв стойки Gecko заново обрабатывал большой inline-SVG; в headless-замерах возникали пики интервалов кадров. | Неизменные векторы стойки, LED и блика перенесены в пять SVG-изображений, которые браузер может кэшировать. Сохранены исходные viewBox, градиенты, формы и координаты. Все девять циклов, включая рисуемый SVG-импульс кабеля, продолжают работать с прежними keyframes. Та же тень применяется к статичной иллюстрации: движущиеся детали целиком лежат внутри её непрозрачного силуэта. |

В CSS шапки проверяется та же форма `scroll(root block)`, которая реально используется; задана явная ненулевая длительность. Анимации дыхания, моргания, ушей, листьев, кольца, LED, кабеля, блика и SLA-механизма сохранены. Размытия, тени и hover-эффекты не удалялись. Ограничение наблюдения/движения вне экрана и паузы скрытого документа сохраняют фазу циклов.

## Область проверки

Просмотрены HTML/Astro-шаблоны, общие и страничные CSS, клиентские скрипты, API и зависимости. Astro выдаёт статический HTML без клиентского UI-фреймворка; серверные/build-зависимости не исполняются в Gecko. Проверены sticky/fixed и отсутствие трансформированных предков панели фильтров, SVG-слои, фильтры, flex/grid, адаптивность, Google Fonts и резервные шрифты, галерея/dialog, Clipboard API и отказ доступа, IntersectionObserver, pointer/keyboard input, reduced motion и отсутствие JavaScript.

Поддержка CSS проверяется в самом браузере, без определения движка по user-agent. Справочные источники: [MDN: scroll()](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/animation-timeline/scroll), [interpolate-size](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/interpolate-size), [Web Animations API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Animations_API/Using_the_Web_Animations_API).

Сумма подключённых на главной JS-файлов выросла с 12 577 до 14 699 байт (gzip 5 213 → 5 999); CSS — 71 040 → 71 403 байт (gzip 16 626 → 16 681). Пять SVG-файлов занимают 9 036 байт (3 006 gzip), при этом HTML уменьшился со 192 148 до 183 871 байт (gzip 32 909 → 30 852). Суммарная локальная gzip-оценка HTML, JS, CSS и этих SVG выросла на 1 790 байт без учёта HTTP-заголовков; появились пять локальных кэшируемых запросов. Главная иллюстрация загружается с высоким приоритетом. Тяжёлые полифилы и библиотеки не подключались.

## Производительность

Firefox: три повтора по 2,2 с с одинаковой начальной фазой циклов (2000 мс). В мобильном viewport стойка предварительно прокручивается в видимую область. До/после используется сохранённая production-сборка; браузеры запускаются последовательно.

| Метрика Gecko | До | После |
| --- | ---: | ---: |
| Desktop 1440×900: медиана p95 интервала rAF | 35,02 мс | 30 мс |
| Desktop: медиана callback rAF за 2,2 с | 122 | 165 |
| Desktop: медиана интервалов более 34 мс за 2,2 с | 19 | 3 |
| Viewport 390×844: медиана p95 rAF | 10 мс | 5 мс |
| Viewport 390×844: интервалов более 34 мс во всех повторах | 0 | 0 |
| Незавершённые cross-fade после 30 быстрых смен фотографии | 30 | 1 |

На обоих размерах все девять ambient-циклов останавливаются вне экрана и сохраняют время. Эти измерения показывают улучшение планирования кадров в данной среде, а не FPS физического дисплея. На desktop отдельные пики сохраняются; полное устранение задержек на любом железе не заявляется.

Контрольная трассировка Chromium прошла на desktop CPU ×1, desktop CPU ×6 и touch viewport 390 px CPU ×6. Во всех трёх профилях: нулевой layout активного первого экрана, нулевой paint/recalc style вне экрана, нулевой paint SLA-механизма, нет оставшихся классов завершённой фильтрации. Paint активного кабеля сохраняется: его dash offset рисуется для сохранения исходной формы импульса.

Сравнены одинаковые фазы при 390 и 1440 px: главная в четырёх фазах, портрет 404, SLA-страница и видимый SLA-механизм. Всего 14 пар PNG в каждом движке, 28 пар суммарно. Снимки также просмотрены визуально, в том числе мобильный первый экран и товар 320 px.

## Воспроизведение

Результаты автоматических проверок и исходные измерения: [FIREFOX-METRICS-2026-10-30.json](FIREFOX-METRICS-2026-10-30.json).

Установить Playwright отдельно от runtime сайта или указать существующую установку. Нужна совместимая тестовая сборка Firefox: обычный установленный Firefox не предоставляет Playwright Juggler. В этой среде используется:

```powershell
$env:TANMEK_PLAYWRIGHT_MODULE = Join-Path $env:TEMP 'tanmek-contact-qa/node_modules/playwright'
$env:PLAYWRIGHT_BROWSERS_PATH = Join-Path (Get-Location) '.firefox-qa.tmp/browsers'
# При первой настройке: node <путь-к-playwright>/cli.js install firefox
npm run build
npm run preview -- --host 127.0.0.1 --port 4321
```

В другом терминале с теми же переменными:

```powershell
$env:TANMEK_BROWSER = 'firefox'
npm run check:ui
$env:TANMEK_BROWSER = 'chromium'
npm run check:ui
npm run check:performance:gecko
npm run check:performance -- --label=gecko-audit-blink --quick --no-visual
```

UI-аудит поддерживает `TANMEK_PREVIEW_URL`, `TANMEK_BROWSER_PATH`, `TANMEK_UI_OUTPUT` и `--functional-only`. Firefox использует тестовое разрешение Clipboard API через настройки браузера; настройки посетителей не меняются. Известные отмены запросов при навигации учитываются отдельно от сетевых ошибок. Для Firefox без JavaScript пропускаются только ожидание Promise `document.fonts.ready` через evaluate и скриншот с таким ожиданием: очередь JS в этом режиме не выполняется; нативные функции проверяются.

Gecko-бенчмарк сам запускает временный HTTP-сервер и закрывает его. `--dist=<каталог>` выбирает сохранённую сборку, `--label=<имя>` — каталог результатов. До изменений `dist/` сохранён в `.firefox-qa.tmp/baseline-dist/`. Для визуального сравнения обоих движков используется существующий сценарий:

```powershell
$env:TANMEK_BROWSER = 'firefox' # затем повторить для chromium
node scripts/check-performance.mjs --label=firefox-audit-before --dist=.firefox-qa.tmp/baseline-dist --visual-only
node scripts/check-performance.mjs --label=firefox-audit-after --visual-only
node scripts/compare-performance-frames.mjs .performance-qa.tmp/firefox-audit-before .performance-qa.tmp/firefox-audit-after
```

Не пересобирать `dist/` во время браузерного прогона: Astro удаляет старый артефакт перед сборкой. CDP-профилирование в `check:performance` предназначено для Chromium; Firefox проверяется отдельным бенчмарком, без подмены недоступных CDP-метрик нулями.

## Ограничения

Headless-тесты с viewport 390 px и touch emulation не заменяют Firefox Android и физический смартфон. CPU ×6 применяется только в Chromium. rAF в Gecko показывает планирование кадров в тестовой среде; он не измеряет реальный FPS экрана, загрузку GPU, энергопотребление или тепловые ограничения. Универсальные 60 FPS на любых устройствах не заявляются.

В проверенном Firefox 151.0 нет нативных межстраничных View Transitions и `text-wrap: pretty`. Полный полифил этих возможностей не вводился: сохраняется предусмотренный сайтом fallback обычной навигации/переноса текста. Пиксельная идентичность сглаживания шрифтов и переносов между Gecko и Blink не гарантируется. Визуальное сравнение выполняется до/после внутри каждого движка. Реальные приложения Telegram/Viber, доставка сообщений, физические устройства, Safari и ручная проверка всех версий Firefox/ESR не входят в выполненные тесты.
